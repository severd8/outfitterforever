# Outfitter Forever — developer notes

Outfitter for **World of Warcraft: Forever** (interface 16001, client 1.60.x).

- Author of the port: `severd8`. License: MIT (keep John Stephen's notice).
- Based on **Outfitter (Retrofit) 5.5.4.3** by GovtGeek: https://github.com/GovtGeek/Outfitter. This repo keeps that history; the remote `upstream` points at it.
- CurseForge project ID: in the `.toc` as `X-Curse-Project-ID`.
- Sister addons: TauntMaster Forever and ToppedOff Forever, whose setup this mirrors.

## Rule for changes

Keep Outfitter exactly as it is. Only change what Forever needs, and keep each change small and marked, so upstream fixes can be merged later (`git fetch upstream`, then merge or cherry-pick).

## Files

- `OutfitterForever.toc` — upstream's Mainline TOC with interface 16001, the folder name `OutfitterForever` and `@project-version@` (filled in by the packager from the git tag).
- `Outfitter.xml` — upstream's `Mainline/Outfitter.xml` (Forever uses the Mainline UI). The Vanilla XML and the old `Mainline/*.lua` copies upstream no longer loads were removed.
- `OutfitterPrefix.lua` — `Outfitter.IsForever`, `Outfitter.IsMainlineClient`, `Outfitter.IsSecret`, `Outfitter:GetSpecialization()`, `Outfitter:GetSpecializationInfo()`.
- Everything else is upstream's code with the Forever changes below.
- `.pkgmeta` leaves upstream's `Documentation` folder (user manual, revision history, images) out of the download: it describes Outfitter, not this port, and nothing loads it.
- `tests/` — offline tests (not shipped). See Testing.
- `.github/ISSUE_TEMPLATE/` — the issue forms (`bug_report.yml`, `feature_request.yml`), each assigning new issues to severd8 (`assignees`). `config.yml` has `blank_issues_enabled: false`, so every issue goes through a form.
- `CURSEFORGE.md` — the CurseForge project description, pasted by hand (not shipped). Since 1.8.0 it's a short, general summary (not the README) so it doesn't need pasting again each release: what's new goes in `CHANGELOG.md`, which the packager uploads with each file. Only update it (and give the whole file to paste) for a whole new kind of feature; never put version numbers in it.

## What Forever is

- The **Mainline client and UI** (Midnight 12.x API, "Camelot" variant of Blizzard's UI). Until build 70170 `WOW_PROJECT_ID` was Mainline's (1); since then the client reports its own, `WOW_PROJECT_CAMELOT` (18). `Outfitter.IsForever` (in `OutfitterPrefix.lua`) is true for either: the Camelot ID, or the Mainline ID with an interface number below 20000. `Outfitter.IsMainlineClient` is true on retail and on Forever. **Never compare `WOW_PROJECT_ID` with `WOW_PROJECT_MAINLINE` directly**: upstream does that to pick its Mainline code paths, and on Forever it's now false. Use `Outfitter.IsMainlineClient` (the file-local `IsMainline` in `Outfitter.lua` is set from it). The tests run under both project IDs.
- The **game is classic**: a ranged slot (and ammo slot, which Outfitter never managed), three warrior stances, talent trees reported as specializations (`C_SpecializationInfo`).
- `LE_EXPANSION_LEVEL_CURRENT` on Forever isn't known, so nothing depends on it for Forever. The tests run with both 0 and 11.
- Removed globals: `GetSpellInfo`, `GetItemInfo`, `GetSpecialization`, `GetSpecializationInfo`, `GetTalentInfo`, `GetTalentTabInfo`, `GetNumSkillLines`, `GetSpellTabInfo`, `GetSpellTexture`, `GetNumQuestLogEntries`, `UnitDefense`, `GetMouseFocus`, `BankButtonIDToInvSlotID`, `EquipmentFlyoutPopoutButton_SetReversed`, `EquipmentManager_UnpackLocation`. Use the `C_*` versions.
- **Secret values**: your own health, mana (`UnitPower`, `UnitPowerMax`), and some names are hidden from addons. Comparing, doing math on or concatenating one throws. Check `Outfitter.IsSecret(v)` first.
- **Auras throw in combat** ("Auras cannot be accessed when secret while tainted"). Call `C_UnitAuras` through `pcall`. `Outfitter:PlayerHasAuraNamed(name, filter)` returns `nil` when auras can't be read, and scripts must then change nothing. `canaccesssecrets()` isn't used on Forever (its value for addons is unknown).
- Registering an event the client doesn't have throws. MC2EventLib registers through `pcall`.
- **Taint**: never assign one of Blizzard's globals (even to wrap it), and never `SetScript` on Blizzard's frames (`MC2AddonLib`'s `hookScript` always uses `HookScript` on Forever). Adding to Blizzard tables (`UISpecialFrames`, `StaticPopupDialogs[key]`) and `hooksecurefunc` / `HookScript` are fine. The tests fail if a Blizzard global or a Blizzard frame's script is replaced.
- Don't register addon functions with `RegisterGameMenuEscHandler`: Blizzard's Escape loop would read the addon's entry and run the rest of Escape (game menu included) tainted.
- Removed or changed on the Mainline API that Outfitter used: `UnitDebuff`, `GetTradeSkillLine` (now `C_TradeSkillUI.GetBaseProfessionInfo`), `C_Minimap.GetTrackingInfo` returns a table (`Outfitter:GetTrackingInfo` handles both).

## Branding (since 1.0.3)

The addon calls itself **Outfitter Forever** everywhere a player can see it; "Outfitter" alone is only used for the original addon it's based on.

- `Outfitter.cTitle` is "Outfitter Forever" in every language file. It's the window title, the minimap menu header, the keybindings group (`BINDING_HEADER_OUTFITTER_TITLE`, and `category` in `Bindings.xml`), the LibDataBroker object's name, and the `[Outfitter Forever]` prefix on chat messages (`MC2DebugLib`).
- The other strings that name the addon were changed in `OutfitterStrings.lua` and `Localization/*.lua`. Slash commands stay `/outfitter`; saved variables, frame names and the folder name are unchanged.
- **Logo**: `Textures/Logo.tga` (64×64) is the TOC icon, the LibDataBroker icon when no outfit is worn (since 1.3.8 the broker shows the worn outfit's icon again, as upstream: `Outfitter.LDB:OutfitEvent`, asked for by a player), and the minimap button, which always shows it (`Outfitter:UpdateCurrentOutfitIcon`; upstream shows the current outfit's icon there). It is made from `art/icon.svg`; `art/logo.svg` / `logo.png` are the CurseForge logo. The Outfits and Options tabs have no background art since 1.2.0 (the faint `LogoLarge.tga` and its two `$parentBackground` textures in `Outfitter.xml` were removed); the flat fill from `OutfitterLook.lua` is all that shows.
- **No About tab**: `OutfitterAbout.lua`, `OutfitterAboutFrame`, the third tab, the `cAbout*` strings and the `CreditPlayersByRealm` list were removed. Credits live in `README.md`, the `.toc` (`X-Credits`) and `LICENSE`. The first tab is "Outfits" (`cOutfitterTabTitle`; each language file says it in its own word for outfits, see Languages).
- The small character-window button (`Textures/Outfitter-Button.blp`) is upstream's art, unchanged. Since 1.2.0 it only shows when the Equipment Manager tab can't be used (see "Character window" below).

## The shared look (since 1.1.0)

Outfitter Forever wears the same look as TauntMaster Forever, ToppedOff Forever and BattleText Forever. It's a restyle only: upstream's frames, scripts and settings do what they always did. Since 1.3.0 the restyle covers the whole window (tabs, outfit rows, footer, options, slot checkboxes and the New Outfit dialog), not just the panel and header, since 1.3.1 the Edit Script dialog too, and now the outfit bar, its two dialogs and Outfitter's menus. Nothing of upstream's stays in its old look.

- `Theme.lua` — **the shared look, and the same file in TauntMaster Forever, ToppedOff Forever, Outfitter Forever and BattleText Forever.** Change it in one repo, then copy it to the other three (it finds its own addon's name and logo from the folder name, in `BRANDS`). It has the colours (`C`), `Fill`, `Border`, `Text`, `FlatButton`, `SwitchWidget`, `Tooltip`, `Panel` (an on-screen panel), `HeaderStrip` (the red bar with the logo and name above an on-screen frame), the settings widgets (`Card`, `Note`, `RowLabel`, `LabeledSwitch`, `Dropdown`, `Slider`, `EditBox`, `ScrollArea`), `Window` (the settings window: header with logo, name and version, tabs down the left, pages, footer), `Disabler` / `ClickableLabel` (greyed-out controls and labels that click like their control; from BattleText Forever, unused here), and `CHAT_PREFIX` (logo and name for chat lines). Loaded just before `OutfitterLook.lua`, the only file that uses it. Don't use Blizzard templates (UIPanelButtonTemplate etc.) in a window with this look.
- `OutfitterLook.lua` — applies it. `Outfitter:ApplyLook()` runs once, right after upstream builds the window's frame art (one marked line in `Outfitter.lua`): it hides that art (`OutfitterFrame.Background`), fills the window with the flat dark panel, adds the red header bar (logo, then the name and version from `OutfitterFrameTitle`, which it hides) a flat X in place of `OutfitterCloseButton`, and a flat scroll track in place of the stone art in `OutfitterMainFrameScrollbarTrench`. What it made is in `OutfitterFrame.Look`. Since 1.3.0 it also: puts flat Outfits / Options tabs under the header (`Look.Tabs`, lit by a hook on `Outfitter:ShowPanel`) and hides `OutfitterFrameTab1/2`; hides the big panel titles; styles each `OutfitterItemN` row (a flat worn box, the menu button as a field with the gold arrow, category names in orange capitals with a gold arrow that turns when folded) and shows the script's name in grey where the gear icon was (`Look.Script`); turns `OutfitterMainFrameHighlight` into a dark red row with a red bar (`Look.SelectedBar`); makes the scroll thumb a thin gold bar; replaces the button bar art with a flat footer holding a flat New Outfit button (until 1.8.1 also an "Outfit scripts" switch, `Look.Scripts`; since 1.8.2 that switch is only in Options, as a player found it in both places); lays the option checkboxes out as switches in three cards (`Look.Cards`; since 1.8.0 they're pages, one showing at a time under page buttons, `Look.OptionsSwitch`, as on the Display tab), except upstream's "Disable all outfit scripts" box (`OutfitterAutoSwitch`, on when scripts are off), which is hidden; since 1.3.1 an "Outfit scripts" switch takes its row (`Look.OptionsScripts`, on when scripts run, `ScriptsSwitch`, calls `Outfitter:SetAutoSwitch`); since 1.4.0 the cards are Automation, Tooltips and Quick access (`cLookAutomation`; the first was "Outfits", the tab's name), every option has the same `T.Tooltip` (its name and one `cLook*Description` saying what it does, the same whether it's on or off; upstream's `AddNewbieTip` showed nothing with the game's enhanced tooltips off, and its On/Off texts went stale after a click), its label turns gold on hover (`SetHover`), labels wrap to a second line instead of being cut off (`LayoutOptions` lays the rows and cards out from the top on every `Update` and when the panel shows: a two-line row is `LINE_H` taller, a hidden row takes no room, and clicks reach as far as the label's text), "Show in item comparisons" reads "Outfits in item comparisons" (`cLookItemComparisons`), and a **Settings** button by the outfit bar's switch (`Look.BarSettings`) opens the bar's settings through upstream's `OutfitBar:DragBar_OnClick("RightButton")`, as a right-click on the bar's handle does; flattens the slot checkboxes on the character; and styles the New Outfit / Rename dialog (`Outfitter:StyleDialog`, hooked on `OpenNameOutfitDialog`). Since 1.3.1 `Outfitter:StyleScriptDialog` styles the Edit Script dialog the first time it opens (hooked on `_EditScriptDialog:Open`): its portrait art, mail icon and button bar are hidden, a header bar carries the title with a flat X (which saves, like the old one), flat Settings / Source tabs sit under the header (`OutfitterEditScriptDialogTab1/2` hidden; a hook on `SetPanelIndex` lights them), the preset script menu is a flat field moved down below the tabs, the script box and every settings field are flat fields (`StyleInput`, with the thin gold scroll thumb and a flat zone button), yes/no settings are switches, and Done / Cancel are flat buttons on a footer strip. The settings fields are made as a script needs them, so a hook on `ConstructSettingsFields` styles new ones.

Hooks on `Outfitter._ButtonBar` (`SetDimensions`, `ShowBackground`; the bar copies these methods as it's made) hide the stone `BackgroundTextures` always and show a flat panel instead (`bar.Look`), which "Hide background" hides; each icon button (`StyleIconButton`) loses the slot art and icon mask, and the template's flyout `Arrow` and `BorderShadow` (alpha 0: `ActionButtonTemplate`'s OnLoad replaces `FlyoutButtonMixin`'s, so the arrow is never sized or hidden, and a mouse press set its atlas at full atlas size, a big yellow triangle over the icon, seen in the icon picker in 1.3.8), gets a cropped icon and a thin gold edge; the outfit you wear gets a bright gold edge, 2 wide, and a gold check badge in the bottom right corner (12×12, `button.WornBadge`, with Blizzard's `UI-CheckBox-Check` tinted dark on it, `button.WornTick`; the badge is on OVERLAY sub-layer 6 and the check on 7, since two textures on the same sub-layer draw in no set order, and in 1.3.5 the badge covered the check; all in `button.WornEdges`, shown by hooks on `SetChecked` and `OnClick`; the template's check art is faded), and hover a light wash pinned to the button's edges (the template's own size and anchors didn't line up once the button was made smaller). Menus: every Outfitter menu (outfit menu, minimap menu, the window's menus) is drawn by its own copy of LibDropdown (`LibDropdownMC-1.0`, used by no other addon). Two marked lines in `Libraries/LibDropdown-1.0.lua` call `lib.StyleFrame(frame)` as a menu panel is set up and `lib.StyleButton(button)` as a line is, and `OutfitterLook.lua` sets both: a flat panel with a gold edge in place of the tooltip border (`NineSlice` hidden), a dark red row under the mouse, gold checks and orange submenu arrows. The row hooks are on `Outfitter._ListItem` (`SetToOutfit`, `SetToCategory`, `OnLeave`), and the dialog hooks on `Outfitter._EditScriptDialog`; they are set when the file loads, because `Outfitter.xml` copies those methods into the frames as it builds them. The look's own strings are `cLook*` in `OutfitterStrings.lua`, translated like the rest (see Languages). - **Display tab** (since 1.5.0, for a player with poor eyesight; two pages since 1.6.0): a third tab under the header, the look's own panel (`Look.Display`), not one of upstream's: `ShowDisplay` puts Outfitter's panel away with `HidePanel` (so `CurrentPanel` is 0 while it shows; `Update` then draws neither panel) and the hook on `ShowPanel` hides it again (opening the window always shows the Outfits tab). Its settings are for the whole account, in `gOutfitter_GlobalSettings.Display` (`Scale` and `TextSize` in percent, `Font` a font file, `Colors` `contrast`/`blue`/`light`; nil is the default; 1.5.0 saved `TextSize` as `large`/`larger`, read as 115/130). **Window size** (50–200%) and **text size** (80–200%) are each a `SizeControl`: a slider in whole steps, applied when the mouse lets go (scaling while dragging would move the slider under the mouse), and a box that takes any number in range to two decimals (a comma works too) on Enter. Window size is `SetScale` on `OutfitterFrame`, on each dialog as it opens (`DisplayDialog`; the bar's settings are re-anchored, since `ShowDialog` places them in UIParent units) and on each menu (`Dropdown.StyleFrame` multiplies the scale LibDropdown has just set). The outfit bar keeps its own size slider. **Text size and font** (`SizeText` / `SizeTextIn`): every font string and edit box keeps its original font in `OFTextBase` and gets that size times the factor, in the chosen font if there is one; menu lines in `Dropdown.StyleButton`. Headings (marked `OFHeading`: header bars, card titles, tabs, categories, dialog sections) can have their own font (`HeadingFont`), and all text an outline (`Outline`: the font flags) and a shadow (`Shadow`; the text's own shadow offset is kept in `OFTextBase.shadow`). Since 1.7.3 a font the game refuses (`SetFont` returns false) leaves the text in its own font, the text is set again after `SetFont`, and `ApplyDisplaySoon` applies everything again 0.3 and 1.5 seconds after a font change and at login: text given a font that's still loading stays blank (a player saw the font field empty while the list, drawn later, showed the font). The **font** menus (`MenuField`: since 1.7.0 the look's own list, `LIST_ROWS` (10) at a time, scrolling with the wheel or a thin bar, clamped to the screen; Outfitter's LibDropdown menus can't scroll and ran off the screen, and `MenuUtil` isn't on Forever) lists LibSharedMedia's fonts when another addon has loaded it, else the game's four (Friz Quadrata, Arial Narrow, Skurri, Morpheus) on Western clients only (they have no Cyrillic, Chinese or Korean letters), and "Game default". The shared pieces from `Theme.lua` (which stays unchanged, being shared) are wrapped (`Fill`, `Border`, `Text`, `Card`, `EditBox`, `SwitchWidget`, `MenuArrow`, `FlatButton`, `HeaderStrip`) and their parts painted again by draw layer (`PaintParts`). Every entry of `C` stays the same table (only its values change: `SetColor`), so what's painted keeps the right reference. `ApplyColors` starts from `DEFAULTS` (C as Theme.lua made it), applies the style (`PRESETS`; four buttons two by two since 1.6.0, after "High contrast" was cut off at four in a row), then **your own colours** (`gOutfitter_GlobalSettings.Display.Custom`, hex codes for `background`, `panels`, `text`, `headings`, `buttons`, `highlight`), each with the shades made from it (`CUSTOM`: background also sets the darker side and field colours and the menus, buttons the hover, toggle, lit tab and selected row, highlight the gold, accents and edges). Enable all / Enable none are buttons coloured like the rest since 1.6.1. Since 1.7.1 every 1-pixel edge (the shared `Border`, Theme pieces' `BORDER` parts, `Box`, the lines under the tabs and over the footers) is registered with `Edge` and sized to one screen pixel at its own effective scale (`PixelSize`: 768 / the physical screen height / the scale, from `GetPhysicalScreenSize`; without it the edges are just not snapped to the pixel grid), again on `FitEdges` (window size, dialogs, menus, lists, `UI_SCALE_CHANGED`, `DISPLAY_SIZE_CHANGED`): at other scales a 1-unit line rounded to a pixel on some sides and to none on others. The tabs and the line under them sit one screen pixel inside the window's edge (they covered it at both ends in 1.7.0; 1.7.1 put them 1 unit in, which is nearly 2 pixels on a 1440p screen and left a dark gap beside the edge, reported in 1.8.1). `MakeTabs` lays them out with `PixelSize` and again on `FitEdges` (`insetList`). Since 1.7.0 the header bars have a colour of their own (`C.header`, a seventh own colour; it was `C.red`, so Buttons changed it), every button and switch has an edge in `C.btnEdge`, which your own Highlight sets exactly (a black button on black still shows), and every flattened button (Cancel included) uses the button colours. `ApplyTheme` applies and repaints, puts Light's dark text on or takes it off (`DarkText` keeps the text's own colour in `OFOrigColor`; `UndarkText`), and redraws the outfit list. On the Colors page each own colour has a swatch (click: the game's `ColorPickerFrame:SetupColorPickerAndShow`, live, Cancel puts the old one back; without it the hex box gets the focus; right-click: back to the style's colour) and a hex box (Enter; `#` optional). Styles can add `hover` (option label under the mouse), `select` (the selected row), `menu` (menu panel: Light keeps menus dark because LibDropdown writes its text white) and `darkText` (Light: `DarkText` / `DarkTextIn` turn the game's white, grey and gold text dark, in the window, in dialogs as they open and in rows through hooks on `_ListItem` `SetTextColor` / `SetToOutfit`; text on the dark header, tabs and buttons is marked `OFKeep` and left alone).

## Forever changes (search for `IsForever`, `IsRetail`, `IsSecret`)

- **Never open or close the character window from addon code** (`ToggleCharacter`, `ShowUIPanel(CharacterFrame)`, `CharacterFrame:Show()` / `:Hide()`). `CharacterFrameMixin:OnShow` and `OnHide` update the player frame's health and mana text (`ShowStatusBarText`, which compares the bar's values and writes `showNumeric` / `lockShow`). Those values are secret, so when the show was started by an addon the compare throws ("attempt to compare a secret number value (execution tainted by ...)"), and the fields it wrote stay tainted. `Outfitter:OpenUI` shows only `OutfitterFrame` when the window is already open; otherwise it prints `cOpenCharacterWindow` and sets `OpenWithCharacterWindow`, and `Outfitter:CharacterWindowShown` (hooked to `OutfitterButtonFrame`'s `OnShow`) opens Outfitter when the player opens the window within a minute. `ToggleUI` no longer closes the character window. The tests' fake client reports an error if the addon touches the window (`W.PlayerTogglesCharacter()` is the player doing it).

- **The outfit stack and what's saved of it** (fixed in 1.2.2; `OutfitterEquipment.lua`): `OutfitStack.Outfits` is the stack you're wearing, bottom to top, and `Settings.LastOutfitStack` is its saved copy (names; an unnamed "temporary" outfit, the gear you put on yourself with no outfit selected, is saved whole). Upstream changes both by position at every step, and two upstream bugs let them drift: on a character's first login `InitializeOutfits` set the stack to `{Normal}` and `OutfitStack:Initialize` then restored the saved `{Normal}` on top of it (Normal twice in memory, once saved), and `CollapseTemporaryOutfits` removed from the in-memory list only. Once they differ by one, the temporary outfit is saved one place past the end, leaving a gap, and `ipairs` never reads it back. Result (reported on a new warrior): after a `/reload` the stack was just Normal, and the stance script's next equip put the character back in its starter gear, emptying every slot filled since, with "Can't find item" for what had been sold. Now `OutfitStack:SaveStack` rewrites the saved copy from the in-memory stack after every change, `RestoreSavedStack` starts from an empty stack, skips duplicates and stops at a gap (what lies past one is from an unknown earlier session), and **`Outfitter:AdoptWornGear`** runs right after the stack is restored: anything you're wearing that the stack doesn't account for goes into the temporary outfit, so a stale stack can never change your gear at login. Empty slots are not adopted (an item can be unreadable right after login, and recording "nothing" would take it off later). `tests/reload.lua` plays these across two fake sessions.
- **Right-click on the minimap button and broker** (asked for by players; a switch in 1.4.2, a choice since 1.6.0): `Outfitter:RightClickAction()` is `open` (the default: `ToggleUI`, which with the character window closed only prints `cOpenCharacterWindow`), `menu` (the outfit menu, as a left-click) or `swap`, saved per character in `Settings.Options.RightClick` (1.4.2's `DisableOpenShortcuts`, set, reads as `menu`). The marked lines in `_MouseUp` (`OutfitterMinimapButton.lua`) and `Outfitter.LDB:OnClick` act on it. **Swap** (`SwapOutfits`): two outfits are picked with "Right-click swap: first / second" in each outfit's menu (`AddOutfitMenu`, marked), kept on the outfit as `SwapSlot` 1 or 2 (a rename keeps it; picking another outfit for a slot frees the old one). `GetSwapTarget` gives the first while the second is worn (an accessory can be worn over the first), the second while only the first is, else the first; the swap wears it with `WearOutfit` (in combat the usual wait), takes the other off if it's an accessory, and shows the key binding message (`cEquipOutfitMessageFormat`, unless outfit change messages are off). With no pair picked it says how in chat. "Open Outfitter Forever" in those menus is left out while the character window is closed unless right-click opens Outfitter (`OpenShortcutWorks`). The minimap button's and broker's tooltip (`ShowBrokerTooltip`, from `_OnEnter`; at the game's default tooltip spot, `GameTooltip_SetDefaultAnchor`, since 1.7.0, so tooltip-moving addons move it; now given the broker's own frame so the tooltip sits by it) always shows (upstream's `AddNewbieTip` showed nothing with Enhanced Tooltips off) and says what right-click does, naming the outfit a swap would put on. In Options it's a label over a menu field (`Look.RightClick`), laid out by `LayoutOptions` as a `field` row.
- **Weapons in combat** (since 1.7.0, asked for by a player; upstream left a TODO for it in `UpdateEquippedItems`): armor can't change in combat, weapons can. While `InCombat`, `UpdateEquippedItems` (marked) calls `Outfitter:EquipWeaponsNow`, which builds an outfit of just the compiled outfit's `cCombatWeaponSlots` (main hand, off hand, ranged) and puts on each weapon that's in the bags: `C_Container.PickupContainerItem`, then `EquipCursorItem` (main hand, off hand, ranged, in that order; the weapon it replaces drops into that bag slot). **`PickupInventoryItem` is protected in combat** (ADDON_ACTION_BLOCKED, reported in 1.8.1: the change list emptied the off hand first through `UnequipSlotID`, which was blocked, so nothing changed), so emptying a hand or moving a weapon from one hand to the other waits like armor; a two-hander puts the off hand away itself (the game does that). The whole outfit still waits (`EquippedNeedsUpdate`) for `PLAYER_REGEN_ENABLED`. The tests' fake blocks `PickupInventoryItem` in combat and records the error.
- **Reopening with the character sheet** (since 1.7.0): Outfitter's frame closes with the sheet (upstream's `OnHide` hides it so it doesn't come back with the window). A hook on `OutfitterFrame`'s `OnHide` (`OutfitterHidden`) notes when that happened while the character window stayed open (another tab, like Reputation), and `CharacterWindowShown` (on `OutfitterButtonFrame`'s `OnShow`) opens it again; closing Outfitter or the window doesn't. **Open with the character window** (`Settings.Options.OpenWithCharacter`, per character; the switch `Look.OpenWithCharacter` in Quick access) opens it every time the sheet shows. Only Outfitter's own frame is shown; the character window is never opened.
- **Slots** (`Outfitter.lua`): `RangedSlot` added on Forever; ranged item types stay in the ranged slot. `OutfitterOutfits.lua` no longer strips the ranged slot from outfits on Forever. `Outfitter.xml` has the `OutfitterEnableRangedSlot` checkbox (anchored to `CharacterRangedSlot`).
- **Character window** (`OutfitterButtonAdjust`): the button goes left of `CharacterFrame.RightPaneToggleButton`; `OutfitterFrame` opens right of `CharacterFrameModeTab1` (Forever has a column of tabs down the window's right edge). The retail `PaperDollSidebarTabs` nudge is skipped. Tab templates use `PanelTabButtonTemplate` (Forever has no `CharacterFrameTabTemplate`).
- **Equipment Manager tab** (since 1.2.0; `Outfitter:CreateSidebarTab`, `UpdateSidebarTab`, `SetUseSidebarTab`): Forever's stats pane has a strip of tabs, `PaperDollSidebarTabs`, with `PaperDollSidebarTab1` (stats), `2` (Equipment Manager), `3` (titles) and `4` (pet). `OutfitterSidebarTab` is Outfitter's own `CheckButton`, a child of the strip, set to all points of tab 2 and five frame levels above it, so it covers the tab and takes its clicks and tooltip. It draws `Textures/Tab.tga` (64×64, square and fully opaque so Blizzard's icon can't show through; made from `art/tab.svg`) under the same atlases as Blizzard's tabs (`UI-Character-Info-StatTab`, and `UI-Character-Info-StatTab-Selected` while Outfitter is open). Nothing of Blizzard's is changed, hooked or clicked: being a child of the strip is what shows and hides it, and its own `OnShow` / `OnHide` run `UpdateSidebarTab`, which shows the small `OutfitterButton` whenever the tab isn't visible (stats pane collapsed, or the option off) and hides it otherwise. `Settings.Options.DisableSidebarTab` (checkbox `OutfitterUseSidebarTab`, per character) turns it off, which uncovers Blizzard's tab; since 1.7.0 the Outfitter tab then sits beside the game's tabs instead (left of `PaperDollSidebarTab1`, 4 apart and the same size, as Blizzard lays its tabs out right to left from the strip's right edge), and the small button shows as well, so both are there. While it's on, the game's Equipment Manager pane can't be reached; sets stored in it still show up as outfits (`SynchronizeEM`). Don't open Blizzard's pane from addon code (`PaperDollFrame_SetSidebar`): that runs Blizzard's code tainted.
- **Baganator** (since 1.2.1; `OutfitterBaganator.lua`): Baganator groups bag items by equipment set. It reads the Equipment Manager itself (so outfits stored on the server always had a group), and its own Outfitter hook (`API/EquipmentSets.lua` in Baganator) waits for an addon named `Outfitter`, which never loads here. So Outfitter Forever registers itself through Baganator's public API, `Baganator.API.RegisterItemSetSource(label, id, getItemSetInfo(location, guid, itemLink), getAllSetNames())`, as "Outfitter Forever" / `outfitter_forever`. `Outfitter.Baganator:Rebuild` (on `OUTFITTER_INIT`, `ADD_OUTFIT`, `DELETE_OUTFIT`, `EDIT_OUTFIT`, `DID_RENAME_OUTFIT`) lists the outfit names in list order and indexes outfits by item ID (and by `cItemAliases`); it calls `Baganator.API.RequestItemButtonsRefresh()` only when the names or item IDs changed. `GetItemSets` answers for one link: outfits with that item ID that pass `OutfitUsesItem`, each with `OutfitBar:GetOutfitTexture` as the icon. **Outfits with `StoredInEM` are left out on purpose**: Baganator's Equipment Manager source already reports them, and Baganator makes one group per reported name, so reporting them twice would give two groups with the same name. The getter is wrapped in `pcall` because Baganator calls it while drawing the bags. `## OptionalDeps: Baganator` makes Baganator load first; if it loads later, an `ADDON_LOADED` watcher registers then. If Baganator ever recognises `OutfitterForever` itself, remove this file or it will be reported twice. Baganator's code was read for its API only; nothing was copied.
- **Outfit order** (since 1.2.0; `Outfitter:SortOutfits`, `CompareOutfits`, `MoveOutfit`, `SortOutfitsByName`, `GetOutfitPlace`): upstream always sorts each category by name. An outfit can now carry `Order` (a number, saved with the outfit in `gOutfitter_Settings`, so per character). A category with no `Order` anywhere sorts by name as before. The first Move up / Move down in a category numbers every outfit in it and swaps two; from then on `SortOutfits` sorts by `Order` and renumbers 1..n each time, so outfits without one (new, or moved in from another category: `AddOutfit` clears `Order` when the category changes) land at the end, by name. The outfit bar and minimap menu read the same arrays, and `MoveOutfit` sends `EDIT_OUTFIT` so the bar redraws. Menu entries are in `AddOutfitMenu` (actions `MOVE_UP`, `MOVE_DOWN`, `SORT_BY_NAME`); the strings are translated (see Languages).
- **Update to current items** (`cSetCurrentItems`, action `SET_CURRENT`, which asks first) is right after Rename at the top of the outfit menu instead of under Rebuild, so saving the gear you put on yourself into an outfit is one click (one marked change in `AddOutfitMenu`).
- **Waiting for combat**: armor can't change in combat, so upstream holds the change until `PLAYER_REGEN_ENABLED`, silently. Until 1.8.1 the port said so in chat (`NoteCombatWait`, `cCombatWait` / `cCombatWaitWeapons`); since 1.8.2 nothing goes to chat (players asked for no chat lines): an outfit that waits (`CombatWaitOutfits`, see Outfit bar states) has a pocket watch where the gear icon was in the outfit list (`look.Wait` on each row, set in the `SetToOutfit` hook, tooltip `cCombatWait`), its waiting edge on the outfit bar, and a `cCombatWait` line in the minimap button's and broker's tooltip (`ShowBrokerTooltip`). `RegenEnabled` redraws the list when they're on.
- **Ammo slot** (since 1.8.0): `AmmoSlot` (slot 0) is added last to `cSlotNames` on Forever, with `INVTYPE_AMMO` mapped to it and an `OutfitterEnableAmmoSlot` checkbox on `CharacterAmmoSlot` (`Outfitter.xml`). On the classic game the slot points at a stack in the bags rather than holding it: equipping is pick up the stack, `EquipCursorItem(0)`, and the stack stays put. So ammo is never taken off: `_EquipmentChanges:addSlot` skips an empty ammo slot, `addUnequipChangesForOutfit` skips ammo, and `execute` never empties the slot first (no bag room is needed). Ammo isn't in `cCombatWeaponSlots`, so it waits for combat to end like armor. Upstream's ammo matching (ignore enchant codes on `INVTYPE_AMMO`) was already there from classic. `tests/fakes.lua` models the pointing slot.
- **Outfit bar states** (since 1.8.0; `OutfitterLook.lua`, `StyleOutfitButton` / `PaintOutfitButton`, hooked on `OutfitBar._Button:Update`): a frame per button with a pulsing 2-pixel gold edge and the game's pocket watch icon (`INV_Misc_PocketWatch_01`) while `Outfitter:OutfitWaitsForCombat` (outfits worn in combat with armor in them, `CombatWaitOutfits`, set in `WearOutfit` and cleared in `RegenEnabled`); a red edge and red-tinted icon when `GetMissingItems` finds a missing item (banked items don't count); and the outfit's key binding (`GetBindingKey("OUTFITTER_OUTFIT"..BindingIndex)`, shortened by `Outfitter:ShortKeyText`) top right, unless `Settings.OutfitBar.HideKeys` (the **Show key bindings** switch in the bar's settings, `ShowKeysCheckbutton`). `BAG_UPDATE_DELAYED` and `UPDATE_BINDINGS` redraw the bar. Nothing is printed in chat.
- **Copy from another character** (since 1.8.0): `Outfitter:SaveCharacterOutfits` copies this character's outfits (plain data, `CopyOutfitData`, without runtime fields, binding, order or Equipment Manager outfits) to `gOutfitter_GlobalSettings.Characters["Name-Realm"]` with name, realm, class and time, after `OUTFITTER_INIT` and on `PLAYER_LOGOUT`. The **Copy from...** button left of New Outfit (`Outfitter.CopyFromButton`, made in a hook on `ApplyLook`; since 1.8.1 an icon button, its name in the tooltip, with New Outfit 100 wide) opens `OutfitterForeverCopyDialog` (`Outfitter:OpenCopyFromDialog`, in `UISpecialFrames`): a menu of `GetOtherCharacters()`, their outfits by category with a switch each (all on), and Copy (n). `Outfitter:CopyOutfits` adds each under `UniqueOutfitName` ("Fishing 2" when the name is taken) and activates its script.
- **Languages**: the strings the port added (`cOutfitterTabTitle`, `cLook*`, `cOpenCharacterWindow`, `cMoveUp`, `cMoveDown`, `cSortByName`, `cSidebarTab*`, `cCombatWait`) are translated in each `Localization/OutfitterStrings_*.lua` (de, fr, cn, tw, kr, ru), in a block marked `-- Outfitter Forever` at the end, using the word each file already uses for an outfit (Outfit, tenue, 套装, 配裝, 장비 세트, комплект). They were written for the port, not by native speakers. Those files are CRLF; keep it. `tests/locales.lua` loads the addon in each language and fails on a missing one or a lost `%s`.
- **Specializations**: `TalentsChanged` (no Titan's Grip), `GetTalentTreeName`, and the preset scripts use `Outfitter:GetSpecialization()`.
- **Warrior stances**: the stance scripts use `Outfitter.IsRetail` (Mainline client *and* not Forever) instead of `IsMainline`, so Forever gets stance forms 1/2/3.
- **Secrets**: spirit regen (`UnitHealthOrManaChanged`), dining (`PlayerIsFull` is false while health is hidden, so Dining ends with the food buff), the Low Health and Equip on Target scripts, aura scanning. Your own `UnitHealth` and `UnitPower` are always secret; `UnitHealthMax` and `UnitPowerMax` aren't.
- **Aura states in combat**: `GetPlayerAuraStates` keeps the last states read before combat on Forever (upstream clears them, which took buff outfits off when combat started).
- **Auras in scripts**: Has Buff, Has Debuff (`"HARMFUL"` filter) and the Trinket Queue buff check do nothing when auras can't be read.
- **Helm and cloak display**: Forever has `ShowHelm` / `ShowCloak`, so outfits apply them (`OutfitterEquipment.lua`).
- **Cooking / Fishing scripts**: `Outfitter:TradeSkillIsCooking()` and `Outfitter:GetTrackingInfo()`.
- **Stats** (`OutfitterItemStats.lua`): Forever uses the original game's stat list, plus spell power.
- **Minimap button** radius is the modern minimap's.
- **Icon picker / cursor icons** (`OutfitterBar.lua`): `C_SpellBook` and `C_Spell`.
- **Escape** (`MC2UIElementsLib.lua`): a hidden, parentless frame (`OutfitterForeverDialogEscape`) in `UISpecialFrames` stands in for open dialogs instead of replacing `StaticPopup_EscapePressed`. Forever's Escape runs `CloseAllWindows`, so the character window closes on the same press.
- **Logo**: `Textures/Logo.tga` (64×64, made from `art/icon.svg`) is the addon list / compartment icon, the minimap button icon whatever you wear, and the broker icon when no outfit is worn (see Branding). Outfit icons are unchanged. `art/logo.svg` / `logo.png` are the CurseForge logo.
- **Folder name**: textures point at `Interface\AddOns\OutfitterForever\`; the version comes from `Outfitter.AddonName`.

## Upstream bugs fixed here (1.0.4, from a code review)

Small and marked, like the Forever changes. Worth offering upstream.

- **Variables missing `local`** (they were written to the global table): `vOutfit`, `vItemLocation`, `vItem`, `vEquipmentChange`, `itemLink` and `_` in `Outfitter.lua`; `offset` in `OutfitterBar.lua` (and two dead `vAnchorOffsetX, vAnchorOffsetY = nil, nil` lines removed); `vOutfit`, `vConfigLine` in `OutfitterOptimize.lua`; `_` in `OutfitterScriptDialog.lua`; `vFunctionFile`, `vFunctionLine` in `MC2DebugLib.lua`. `OutfitterInventory.lua` wrote the global `_` on every bag and inventory item scan; it now has a file-level `local _`. The tests fail on any global the addon makes that isn't one of its own names (`W.addonGlobals`).
- **Wrong variable names**: `pItem` → `item` (`Outfitter.OutfitItemSelected`), `self` → `Outfitter` (`Outfitter.InitializeFrame`, called with a dot), `pItemName` → `pItemInfo.Name` (`AddOutfitStatItem`), `pSlotID` → the location's slot (`GetItemLocationLink`). Each one turned an error message into a Lua error.
- **`GetLinkFromTooltip(tooltip)`** asked `GameTooltip` whatever tooltip it was given, so comparison tooltips got the hovered item's outfit list. It asks the tooltip it's given.
- **Icon picker, "Inventory" set** (`OutfitterBar.lua`): compared with a variable that doesn't exist there, so worn items were never listed.
- **Gear changes** (`_EquipmentChanges:execute`): the loop runs in `pcall`, so an error can't skip the line that turns sound effects back on. The error is raised again afterwards.
- **Script settings** (`ParseScriptFields`, `ActivateScript`, since 1.3.7): a `-- $SETTING` line is compiled as `return {...}` and run; a line that threw when run, a table setting with no `type` (or a type that isn't text), or a setting that's a number or `true` was a Lua error, which also stopped whatever was parsing (activating the scripts at login, the Edit Script dialog). The line now runs in `pcall`, and those cases return `nil, message`; `ActivateScript` prints which outfit's script didn't start and why, as it does for a script that won't compile.
- **Tooltip lines with no text** (`ParseTooltipLine`, `ParseGemLinkForUniqueEquips` in `OutfitterInventory.lua`, since 1.7.2): reading an item's tooltip assumed every line had text; an addon that blanks a line (Remove Sell Price NG, the sell price) made it a Lua error that stopped Outfitter at login. Such lines are skipped.
- **`string.utf8reverse`** (`Libraries/UTF8/utf8.lua`, since 1.3.1): it wrote the global `c`, and read `strbyte(pos)` (a byte of the number) instead of `strbyte(s, pos)`, so text with a three-byte character threw "Invalid UTF-8 character". Outfitter never calls it, but the library puts it in the shared `string` table, where any addon can.

Known and left alone (they read a name that doesn't exist and get `nil`, which happens to be what the code needs): `vExpectedInventoryCache` in the bank functions, `pSettings` in the Rogue Stealth preset, `return change` in `_EquipmentChange:construct`, `specName` in `InitializeTalentTreeOutfits` (upstream switched that function off), `pForceState` in `MC2UIElementsLib`. `MC2DebugLib` defines a global helper `tern`; nothing uses it. About 110 functions (roughly 1,600 lines) aren't called from anywhere in the addon. Some are meant for players' own scripts, so they stay.

`luacheck` can't read `OutfitterInventory.lua` as it is (`\|` and `\:` in two patterns, which the game's Lua accepts), so it reports nothing for that file. To check it: `sed 's/\\|/|/g; s/\\:/:/g' OutfitterInventory.lua > /tmp/inv.lua && luacheck /tmp/inv.lua`.

## Testing

Run from the repo root before every commit:

    lua5.1 tests/run.lua

- `tests/wow.lua` — a fake Forever client. Globals resolve against `tests/forever_api.lua`; anything Forever doesn't have is nil, so calling a removed API fails like it would in game. Frame methods are checked against Forever's widget API. Loads the `.toc`, builds the XML (templates, `$parent` names, scripts, OnLoad order) and runs events and `OnUpdate`.
- `tests/fakes.lua` — the game state: a level 60 character, gear, bags, a cursor that moves items like the real one (including two-handers pushing off-hands into bags, and no armor changes in combat), auras (buffs and debuffs) that throw in combat, secret health and mana, minimap tracking, the trade skill window, Forever's character window frames.
- `tests/run_tests.lua` — the scenarios: load and log in, button/window placement, saving and wearing outfits, the ranged slot, combat, stance and other scripts (buffs, debuffs, dining, cooking, fishing), helm display, slash commands, minimap menu, tooltips, riding, options, the Equipment Manager tab, outfit order, Baganator (a fake one, present before the addon loads in half the runs and loaded later in the other half), plain panel backgrounds, Escape, error messages, the icon picker, sound effects after a failed gear change, the Edit Script dialog's look and the Options "Outfit scripts" switch, and that no Blizzard global or frame script is replaced and no stray global is made (`string.utf8reverse` is called for that). A fake the addon uses that Forever doesn't have also fails.
- `tests/forever_api.lua` (`PaperDollSidebarTab2` was added to its `ui_frames` by hand for 1.2.0; rerunning the script adds it too) is generated by `tests/tools/make_forever_api.py` from Blizzard's Forever UI source (https://github.com/Gethe/wow-ui-source, `forever` branch) and the client's API reference (https://github.com/imperial64/forever-addon-dev). Rerun it after using a new API or Blizzard frame (instructions at the top of the script).

- The fake client (`tests/wow.lua`) gives `FauxScrollFrameTemplate` its scroll child, as Forever's does (the generated parts list doesn't carry `<ScrollChild>`; without it the icon picker was never built in the tests, and `OUTFITTER_INIT` printed an error), `SetColorTexture` clears a texture's file, as in the game, and textures keep their draw layer and sub-layer (`GetDrawLayer`). Since 1.8.2 `PickupInventoryItem` is blocked in combat (it records an ADDON_ACTION_BLOCKED error, as the game does) and `GetPhysicalScreenSize` is in `forever_api.lua` (by hand; the tests fake it only where they check pixel sizes). Since 1.7.0 it has `PaperDollSidebarTab1` (added to `forever_api.lua`'s `ui_frames` by hand, like Tab2) and `GameTooltip_SetDefaultAnchor` (it notes the owner in `__defaultAnchor`). Since 1.5.0 it keeps scale (`GetEffectiveScale` multiplies up the parents) and fonts set with `SetFont` (cleared by `SetFontObject`). Since 1.4.0 it keeps hit rect insets, and text width is about 6 px a letter (11 for Chinese and Korean), counted in letters, not bytes.
- `tests/locales.lua` — the addon in each shipped language: the port's strings are there, the window builds without errors, the option cards fit in the window, and the French Equipment Manager tab option wraps onto two lines.
- `tests/reload.lua` — scenarios across a `/reload`: each session is a fresh fake client, and the saved settings are copied between them as plain data, the way the game writes them. A new character putting gear on and reloading, settings saved by 1.2.1 (with and without a gap), empty slots at login, your own gear above and below an automatic outfit, and the Birthday Suit.

Only testable in game: layout and looks, real item swapping timing, Forever's exact secret and taint rules.

## Releasing

1. Run the tests and add a section at the top of `CHANGELOG.md`.
2. Commit and push to `main`. The **Tests** workflow must be green.
3. Tag in GitHub Desktop (History → right-click the commit → Create Tag → e.g. `v1.0.1` → Push origin).
4. **Package and release** runs the tests again and uploads to CurseForge. Needs the `CF_API_KEY` repository secret.
